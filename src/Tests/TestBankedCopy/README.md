Run `make test-banked-copy BANK_TEST_CC=/path/to/cl65 BANK_TEST_EMU=/path/to/x16emu BANK_TEST_ROM=/path/to/rom.bin` with cc65 Git 2ea1df8 (or a compatible compiler) and X16 emulator r49 with its ROM. The suite uses the product CFLAGS, not a separate optimization profile. The emulator's VIA2 option supplies the test IRQ timer; no game files or SD image are required.

The permanent native C suite links production `helpers.c`, `memoryManager.c`, and `bankedCopy.s`. It checks bank reads/writes, unrelated bank numbers, CPU-page and 16-byte unroll boundaries, 192-byte cross-bank chunks, 512-byte IRQ service boundaries, full 8 KiB windows, zero length, same-bank copies, explicit split-bank objects, guard bytes, return pointers, and incoming IRQ state. It also reaches the actual buffer-refill and reallocation helpers: copied bytes survive reallocation and the old allocation becomes reusable only after return. Test helper/allocator code segments are linked in low RAM; their data still uses real X16 banks. The suite trampoline follows the product wrapped-call ABI.

The IRQ regression installs a continuous 1000-cycle VIA2 timer. While copying, its handler switches banks and overwrites all eight cc65 scratch-pointer bytes, requiring the copy to preserve and resume its state. It measures the largest interval between IRQ services and requires less than 10000 cycles (1.25 ms at 8 MHz). The initial implementation failed at 110743 cycles. The revised implementation measures about 7700 cycles. A caller entering with IRQs disabled retains its own critical section; this latency bound applies to callers entering with IRQs enabled.

Performance cases retain the original C copy, original 50-byte cross-bank choreography, and original buffer-refill body as benchmark references only. Production has one assembly copy implementation and no fallback switches. The suite measures 1-, 6-, 50-, 500-, 2048-, and 8000-byte copies with IRQs both enabled and disabled, plus the real 500-byte refill and cross-bank paths. Each direct and cross-bank workload requires at least a 5% cycle reduction; the real refill must beat its original C implementation. Hardware IRQ sources are temporarily disabled only during direct-copy timing, while the incoming CPU I flag is varied; this includes yield overhead without IRQ-handler timing noise. The separate live timer case verifies actual delivery. Branch placement can affect precise percentages.

Measured with product compiler flags: IRQ-enabled 32000-byte copies use about 7% fewer cycles, four 2048-byte copies about 7% fewer, actual 500-byte refills about 16% fewer, and cross-bank 500-byte refills about 53% fewer. These are resource lookup/refill timings, not total room or inspect frame times.

Copies remain synchronous. Callers retain ownership throughout the transfer and select the next bank explicitly at window boundaries; adjacent banks need not belong to the same object. The assembly services pending IRQs with the original bank mapped after at most 512 copied bytes, saving its pointers and counters on the CPU stack while interrupts run. It never leaves a queued transfer or an IRQ reference to the old resource.

All generated objects, programs, and emulator files belong to a unique case directory under `obj/cx16/tests/banked-copy`; the target removes it on success, failure, timeout, or interruption. Allocated test resources are released before exit. The test linker provides inert bank-size symbols for the unused product resource-loader initializer; no manual fixtures are staged.

Build the entire product into its existing output tree with `make PROGRAM=obj/cx16/agi CC=/path/to/cl65`. The makefile names the supported cc65 stack optimization stages, selects W65C02 assembly, and places its map in the target object directory.

Audit scope: `memCpyBanked` is the shared resource lookup/copy helper. The cel-to-VERA pixel loop already uses assembly, and loader drawing goes through text rendering. Room, inventory, and loader screenshot parity and total frame time still require a real game run. Existing unconditional `stp` instructions in `showObj.c` and `showObjAsm.s` block inspect acceptance; this change does not remove those unrelated debug stops.
